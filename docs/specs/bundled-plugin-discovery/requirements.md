# 发行包内插件自动发现 — 需求

**Spec**: `bundled-plugin-discovery`
**状态**: 已完成实现与本功能验收（2026-10-22）；用户批准及验证证据见 `tasks.md`

## 1. 背景

预编译发行包已经包含主程序和全部插件，主程序与 `plugins/` 同级（`README.md:67-78`、`.github/workflows/release.yml:212-215`）。但当前插件根目录只考虑显式环境变量和原用户默认目录，不会发现包内插件（`src/plugin.rs:1173-1183`）。因此使用者解压后仍须手工设置 `NETUTILS_PLUGIN_DIR`（`README.md:80-98`），未达到发行包应有的开箱即用体验。

## 2. 目标

完整解压发行包后，无需设置环境变量或重新安装插件，即可使用包内插件子命令。插件发现不依赖启动时的工作目录，目录选择对执行和管理命令保持一致。

## 3. 非目标

- 不引入多个插件根目录叠加、跨根版本选择或独立的安装/运行目录配置。
- 不自动下载、复制、移动或安装缺失插件。
- 不改变插件协议、插件自身行为、既有别名或子进程权限模型。
- 不混入前次安全审计发现的凭据脱敏、重定向或代理解析修复。
- 不调整发行归档布局，不修改已发布的 GitHub Release，不把旧版二进制描述成已支持新行为。
- 不重新定义显式环境变量值、原用户默认目录或 `PATH` 的其他既有语义。

## 4. 需求

### R1 发行包零配置使用

完整解压现有布局的发行包后，应能直接发现随包插件。

**验收标准**

- 未设置 `NETUTILS_PLUGIN_DIR` 时，可直接运行包内已有的插件子命令，无需 `cargo install` 或其他初始化步骤。
- 从不相关的工作目录通过绝对路径启动，或将主程序目录加入 `PATH` 后启动，均发现同一包内插件目录。
- 整体移动解压目录后，新位置的主程序仍能发现随包移动的插件，不保留旧位置依赖。
- Windows、Linux、macOS 的现有发行包布局均适用。

### R2 明确目录优先级并兼容原安装方式

每次调用选择一个有效插件根目录，优先级如下：

1. 显式设置的 `NETUTILS_PLUGIN_DIR`。
2. 正在运行的主程序同级、已存在的 `plugins/` 目录。
3. 原有用户默认目录及既有兜底行为。

**验收标准**

- 显式环境变量优先，即使其指向尚不存在的目录，也不能被包内目录或用户默认目录替代。
- 未设置环境变量，且包内目录与用户目录均有同名插件时，包内目录胜出。
- 已存在的空 `plugins/` 目录也可作为便携安装的有效根；同名普通文件不能作为插件目录。
- 没有包内目录，或无法确定主程序位置时，保留原用户目录的使用体验，不因自动发现失败而崩溃。
- 有效根中找不到指定插件时，保留现有执行路径中的 `PATH` 回退和未安装提示，不继续叠加另一管理根。

### R3 启动位置无关且搜索范围固定

自动发现只针对主程序同级的随包目录，不把调用者的工作目录当作发行包位置。

**验收标准**

- 工作目录或其祖先目录中的同名 `plugins/` 不得成为新增的自动发现来源。
- 不执行任意向上遍历，也不为发现插件扫描无关目录。
- 未发现包内目录时，不因启动或列举插件而创建该目录、抢占原默认根。

### R4 查询、运行与管理目标一致

自动发现不应造成“列出一个位置、运行另一个位置、安装或删除第三个位置”的分叉。

**验收标准**

- `plugin dir` 显示当前有效根；该根统一用于包内插件的列举、执行、安装、更新、删除和锁文件读写。
- 自动选中包内根后，安装、更新、删除操作针对该根；不会静默改到用户默认目录。
- 相同插件存在于其他候选根时，对当前根的管理操作不得修改另一个根中的副本。
- 执行时既有的 `PATH` 回退不等于把 `PATH` 插件纳入当前根的安装管理范围。
- 有效根不可写时，写操作明确报错，不通过改写另一个根来假装成功。

### R5 发现不要求写权限，现有输出契约不变

仅使用已解压的插件，不应产生额外安装或记账要求。

**验收标准**

- 包内插件具备读取和执行权限但目录不可写时，核心的 `plugin dir`、列举及执行分派仍可使用。
- 核心的发现、列举及执行分派不创建目录、补写锁文件或修改另一个插件根；插件自身的文件操作不属于此保证。
- 包内插件缺少 `plugin-lock.json` 时，沿用现有状态与 `unrecorded` 完整性语义，不为自动发现伪造安装或校验记录。
- 既有 JSON 字段名、类型、顶层形状、插件别名分发及子进程退出码传播保持不变。

### R6 文档与发布说明随行为同步

用户应能从使用说明和后续发行说明中发现零配置用法及目录选择规则。

**验收标准**

- 中英文 README 明确说明：包含本功能的发行包解压即可使用随包插件，设置 `NETUTILS_PLUGIN_DIR` 是可选覆盖，不再是必需步骤。
- 说明目录优先级，以及便携根被选中后安装、更新、删除与其同根；只读场景可显式指定可写根。
- 后续发布正文与示例同步更新，不再要求使用者为完整发行包先手工设置插件目录。
- 文档不声称未包含此修复的旧版二进制已获得自动发现能力。

## 5. 已批准的关键契约

- 自动发现仅限主程序同级的 `plugins/`，不根据工作目录或任意祖先目录就近搜索。
- 包内目录优先于用户默认目录；仍只有一个有效根，不合并两个目录中的插件。
- 自动选中包内根后，管理命令也操作它；不可写时明确失败，用户可以显式切换到其他根。
